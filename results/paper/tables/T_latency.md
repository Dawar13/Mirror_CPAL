Checks: float64, float32 and bfloat16 agreement of the efficient model with the dense model it was built from (T_latency_checks).
Which analytic speed-up: measured / analytic uses analytic (M2), the timing script's count of the implementation it timed, so numerator and denominator describe the same model. Analytic (collector) is the structured count of tables/cost_model.md that T_main_zeroshot reports. The two agree for every variant except V-local (M2 also counts one d x d rotation of the CLS feature, below 0.01%). For V-local the timed implementation stores Wo dense in the block's basis, because M1 projected Wo with A_(l+1) rather than the block's input operator (keeping it structured would need a second rotation per block, vlocal_r2, not run): Wo then costs d x H dh multiply-adds per token instead of its free-parameter count. Column wo_dense_extra_gflops (CSV) recomputes that extra cost from runs/m1/m1_ranks.csv; with the CLS rotation it accounts for the whole gap between the two GFLOPs counts (column analytic_gap_unexplained_gflops). The same choice is why V-local's params here (the stored dense Wo) exceed its count in T_main_zeroshot. Basis rotations are counted the same way in both (one d x d per converted block).
